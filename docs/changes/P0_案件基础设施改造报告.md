# 《通往异世界的列车》P0 案件基础设施改造报告

**作者：Manus AI**  
**日期：2026-08-16**

## 结论

当前版本原本有 `inv`，但 `inv` 只显示玩家背包中可携带的物品；它不能显示任务目标、已经读过但不可携带的证据、失败代价、已知 NPC 信息或下一步调查方向。因此，`inv` 不能替代案件线索册。

此外，原有房间通过 `room:add_obj(...)` 创建的便签、书籍、开关等对象属于房间共享 `content`。不同玩家处在同一个房间时，会共同看到、拿走或影响这些对象；这就是此前书店《暴风之眼》搜索提示与自动化测试出现相互影响的根源。每个角色的 `game_tags` 与存档则天然是私有且可持久化的，适合作为案件状态承载层。

本次已在生产版本实现最小 P0 基础设施：**私有案件状态、线索册命令、关键场景的失败前进，以及《暴风之眼》入口的私有发现状态。**

## 新增与改造

| 能力 | 状态 | 说明 |
|---|---:|---|
| `journal` | 已上线 | 查看当前角色专属的案件标题、摘要、目标、线索与最近一次失败代价。 |
| 私有案件状态 | 已上线 | 数据保存于 `player.game_tags.casebook`，随 `save`、断线和正常下线持久化。 |
| 私有《暴风之眼》发现 | 已上线 | 每位玩家独立完成 `search 书架` 与 `read 暴风之眼`；不再依赖共享书籍是否已经生成。 |
| 6号车厢线索册 | 已上线 | 玛拉规则、神秘便签、电车示意图会按玩家分别写入线索册。 |
| 3号车厢失败前进 | 已上线 | 第一次侦查失败给出明确替代行动；第二次侦查保证发现开关；潜行/逃跑失败记录代价和可继续方案。 |
| 显式存档 | 既有功能 | `save` 仍保存地点、属性、SAN、技能、背包、剧情标签和新增案件状态。 |

## 玩家操作

```text
journal                 # 查看全部案件与当前目标
journal otherworld_train # 只查看列车案件
journal storm_eye        # 只查看《暴风之眼》章节入口
save                    # 保存当前进度与线索册
```

列车开局的推荐体验流如下：

```text
look
say 理智 mara_vane
get mysterious_note
look mysterious_note
look train_map
journal
go east
```

3号车厢中，若侦查第一次失败，玩家不会被无提示地卡住：可再一次 `perform 侦查`，或直接 `perform 潜行`。第二次侦查会保证发现电路开关。潜行触发怪物后，`journal` 会记录逃跑或战斗选择；逃跑失败也不会删除剧情进度。

书店中，玩家可独立完成：

```text
say 帮助 elias_thorne
search 书架
save
read 暴风之眼
journal storm_eye
```

## 验证结果

隔离测试角色已完整验证：注册、票务引导、进入6号车厢、与玛拉交谈、拾取并阅读便签、查看示意图、执行 `journal` 和 `save`。线索册正确显示列车案件、玛拉规则、神秘便签与电车示意图。

另有独立 Lua 单元测试创建两名模拟玩家：A 记录的线索不会出现在 B 的 `game_tags.casebook` 中，双方目标互不覆盖。测试结果为 `CASEBOOK_ISOLATION_PASS`；LuaMUD 和 Agent API 服务均为健康状态。

## 面向《暴风之眼》的复用方式

后续制作正式副本时，每个案件均应复用 `Casebook`：使用 `Casebook.start_case` 建案，使用 `Casebook.add_clue` 记录个人线索，使用 `Casebook.set_objective` 推进目标，使用 `Casebook.record_setback` 将失败转换为代价与后续选择。

这消除了“一个玩家搜过书架，其他玩家就不能获得线索”的关键风险。仍需在正式多人副本开发时进一步把怪物、机关、倒计时和房间出口改为玩家实例或副本实例；本次改造已解决最先影响调查流程的线索与章节发现层。
